# Design System

> Visual and interface design system for the Ayur Clinic website.

## Overview

The Ayur Clinic design system provides a consistent foundation for the website's visual language, typography, spacing, components, and responsive behaviour.

The goal is to create a patient-facing experience that feels professional, calm, modern, and reassuring.

The design prioritises clarity over decoration. Every visual element should support readability, navigation, accessibility, or the overall patient experience.

The core design principles are:

- Clear visual hierarchy
- Calm and professional aesthetics
- Consistent spacing
- Readable typography
- Reusable interface patterns
- Responsive layouts
- Accessible interactions
- Deliberate use of colour
- Minimal unnecessary decoration

---

## Visual Direction

The visual direction moves away from the typical corporate or overly clinical healthcare website.

The interface combines:

- Editorial-style typography
- Clean modern layouts
- Generous whitespace
- Soft neutral surfaces
- Botanical-inspired accents
- Structured content
- Refined interface elements

The objective is to create an experience that feels trustworthy and professional without feeling cold or overly institutional.

---

## Colour System

The colour palette is intentionally restrained.

The primary visual direction includes:

- Soft neutral backgrounds
- Warm off-white surfaces
- Deep charcoal text
- Muted green accents
- Subtle borders
- Low-contrast supporting surfaces

Colour is used purposefully rather than decoratively.

Accent colours should be reserved for:

- Calls to action
- Important interactive elements
- Navigation states
- Supporting visual emphasis

Text and background combinations should maintain sufficient contrast for readability and accessibility.

---

## Typography

Typography is a major part of the Ayur Clinic visual identity.

The system uses clear hierarchy to guide users through healthcare information.

The typography system includes:

- Display headings
- Section headings
- Eyebrow labels
- Body text
- Supporting text
- Navigation labels
- Interactive labels

Large headings are used selectively to create visual impact while maintaining readability.

Body content prioritises clarity and comfortable reading.

Typography should remain consistent across pages rather than introducing unrelated font styles or sizes for individual sections.

---

## Typography Hierarchy

The interface follows a structured hierarchy.

### Display Headings

Used for major page introductions and high-impact sections.

These headings create the strongest visual emphasis and establish the editorial character of the platform.

### Section Headings

Used to introduce major content areas.

Section headings should clearly communicate the purpose of the content that follows.

### Eyebrow Labels

Small labels used above headings to provide additional context and structure.

These are useful for categorising content without creating unnecessary visual weight.

### Body Text

Used for primary informational content.

Body text should prioritise:

- Readability
- Appropriate line length
- Comfortable line height
- Sufficient contrast

### Supporting Text

Used for secondary explanations and contextual information.

Supporting text should remain visually subordinate to primary content while still maintaining readability.

---

## Spacing System

Whitespace is treated as part of the information architecture.

Spacing is used to create separation between:

- Major sections
- Related content
- Headings and body content
- Cards
- Interactive elements
- Navigation components

The design avoids excessive visual density.

Consistent spacing patterns should be reused throughout the application rather than applying arbitrary margins and padding to individual components.

The result should feel calm, organised, and deliberate.

---

## Layout

The layout system is based on consistent content containers and responsive spacing.

Pages are structured around:

- Full-width sections
- Centred content containers
- Flexible grids
- Responsive columns
- Clear visual separation

Content width should remain controlled to prevent long lines of text and improve readability.

Layouts should adapt based on screen size rather than simply scaling down desktop designs.

---

## Components

The interface is built around reusable components.

Common components include:

- Header
- Navigation
- Footer
- Buttons
- Cards
- Content sections
- Resource cards
- Service cards
- Form controls
- Interactive calculator controls
- Location information blocks

Reusable components help maintain consistency and reduce duplicated implementation.

---

## Buttons

Buttons provide clear actions throughout the application.

The system supports clear visual distinction between:

- Primary actions
- Secondary actions
- Supporting actions

Primary actions should receive the strongest visual emphasis.

Secondary actions should remain visible without competing unnecessarily with the primary action.

Buttons should maintain:

- Clear labels
- Sufficient touch targets
- Visible hover states
- Keyboard focus states
- Consistent spacing
- Accessible contrast

---

## Cards

Cards are used to group related content and create clear interaction boundaries.

Examples include:

- Services
- Patient resources
- Team members
- Pregnancy tools
- Location and parking information

Cards should use consistent:

- Padding
- Border radius
- Typography hierarchy
- Spacing
- Hover behaviour

Cards should not be overused purely as decoration.

They should represent meaningful content or interaction groupings.

---

## Navigation

Navigation is designed to make important information easy to discover.

The primary navigation provides access to key areas such as:

- About
- Meet the Team
- Services
- Patient Resources
- Contact

Navigation should remain clear across desktop and mobile devices.

The mobile navigation should prioritise:

- Clear hierarchy
- Large touch targets
- Simple interaction
- Accessible keyboard behaviour

---

## Forms and Interactive Controls

Interactive elements should maintain consistency across the application.

This includes:

- Inputs
- Select controls
- Date inputs
- Radio controls
- Buttons
- Calculator options

All controls should provide:

- Clear labels
- Visible focus states
- Accessible interaction
- Appropriate error messaging
- Sufficient spacing
- Clear selected states

The goal is to make interactive experiences easy to understand without requiring unnecessary explanation.

---

## Responsive Design

The design system supports:

- Desktop
- Laptop
- Tablet
- Mobile

Responsive behaviour is considered at the component level.

Key responsive changes include:

- Navigation collapsing into a mobile-friendly experience
- Multi-column layouts adapting to fewer columns
- Typography scaling appropriately
- Spacing adjusting for smaller screens
- Interactive elements maintaining comfortable touch targets

The goal is to preserve the quality of the experience across devices rather than simply shrinking the desktop layout.

---

## Micro-interactions

Interactions should feel subtle and intentional.

Examples may include:

- Button hover transitions
- Navigation state changes
- Card hover feedback
- Input focus states
- Smooth visual transitions

Animations should support usability rather than distract from content.

Motion should remain restrained and should not interfere with accessibility or reading.

---

## Accessibility

Accessibility is considered part of the design system.

The interface aims to support WCAG 2.2 AA principles where applicable.

Key considerations include:

- Sufficient colour contrast
- Visible keyboard focus states
- Clear interactive states
- Readable typography
- Logical heading hierarchy
- Semantic HTML
- Accessible labels
- Comfortable touch targets
- Responsive text sizing

Reusable components should be designed with accessibility in mind from the beginning.

---

## Design Consistency

The design system is intended to prevent visual inconsistency as the application grows.

New pages and components should follow the established principles for:

- Typography
- Colour
- Spacing
- Layout
- Buttons
- Cards
- Interactions

New interface patterns should only be introduced when an existing component or pattern cannot reasonably solve the problem.

---

## Design Approach

The central principle behind the Ayur Clinic design system is:

> Calm, clear, and intentional.

The website should feel premium without becoming visually excessive.

The interface should feel modern without relying on short-lived design trends.

Every design decision should support one or more of the following:

- Patient understanding
- Readability
- Navigation
- Accessibility
- Trust
- Consistency

---

## Current Status

**Under Active Development**

The design system continues to evolve alongside the website.

Typography, spacing, component patterns, responsive behaviour, and interactions will continue to be refined as development and testing progress.

The objective is to maintain a cohesive visual language while allowing the system to evolve based on real product requirements.
